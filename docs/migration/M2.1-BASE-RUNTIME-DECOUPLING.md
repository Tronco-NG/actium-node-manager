# Gate M2.1 — Base Runtime decoupling

## Alcance

Este gate desacopla el arranque universal de Actium Node Manager del snapshot
legacy de Ecosistema Aegis. No mueve, copia ni regenera `PAYLOAD.json`, no usa
symlinks y no ejecuta `prepare:payload`.

## Causa reproducida

La ruta fatal era:

```text
Tauri startup
  → src/main.ts start()
  → invoke("get_system_info")
  → src-tauri/src/lib.rs get_system_info
  → payload_dir(app)
  → app.path().resolve("node", Resource)
  → verify_payload(PAYLOAD.json)
  → startup fatal si resources/node no existe
```

El nuevo repositorio no contiene `src-tauri/resources/node`, por diseño. La
causa no era un problema de DNS, Control Plane ni Supervisor: el diagnóstico
local se abortaba antes de completar el primer estado de runtime.

## Contrato M2.1

`get_system_info` ya no resuelve recursos Tauri ni verifica un payload. Lee el
registry opcional desde el data root canónico del canal:

```text
<supervisor-data-root>/extensions/registry.json
<supervisor-data-root>/extensions/installed/<product_id>/<bundle_id>/manifest.json
```

El registry se crea vacío si no existe y devuelve:

```text
base_runtime_state = BASE_RUNTIME_READY
extension_count = 0
extension_registry_state = NO_EXTENSIONS
extensions = []
```

Los bundles usan `actium-product-extension-bundle@1.0.0`, exponen health,
capabilities y digests de artefactos. El engine M2.2 verifica firma y contenido
antes de instalar; un bundle inválido degrada el registry de extensiones sin
convertir la ausencia de extensiones en un fallo del Base Runtime.

La UI de `Infraestructura` muestra Base Runtime, estado del registry, cantidad
de extensiones y `NO_EXTENSIONS`. La ausencia de bundle es observable y
operable, no fatal.

## Boundary legacy

`LegacyAegisPayloadAdapter` es la única frontera explícita para operaciones
legacy que todavía requieren un bundle. Sólo se invoca desde comandos de
instalación/actualización que lo necesitan; nunca desde startup ni desde el
diagnóstico base. Si no hay bundle externo, falla cerrado con
`PRODUCT_EXTENSION_BUNDLE_REQUIRED`. Su condición de retiro es
`Product Extension Bundle v1`.

Supervisor conserva `payload_root` como ubicación opcional de compatibilidad.
`--check`, el self-test y el arranque del daemon aceptan esa ruta ausente;
`--verify-payload` permanece explícitamente estricto. Los instaladores no
requieren `-Payload`/`--payload` para instalar el Base Runtime.

## Build y límites

- Frontend, Core, Supervisor y Tauri se construyen sin el PAYLOAD de Aegis.
- El paquete de terminal legacy sólo se intenta si existe un bundle externo.
- `src-tauri/tauri*.conf.json` no registra `resources/node`.
- El PAYLOAD permanece únicamente como artefacto congelado del consumidor Aegis.
- No se hicieron operaciones remotas, enrollment real ni cambios de autoridad.
- `source_commit`, `build_id` y `binary_sha256` se mantienen en el diagnóstico.

## Siguiente gate

M2.2 implementará el Product Extension Bundle v1 firmado y reemplazará la
compatibilidad legacy basada en `PAYLOAD.json`. Hasta entonces, Aegis sigue
siendo el owner del snapshot congelado y Node Manager sólo opera su Base Runtime
universal más el registry externo opcional.
