## Cadena operacional reconciliada

```text
Product/Deployment Trust
        ↓ publicación y políticas en Center
Site Runtime Authority histórica (delegación acotada)
        ↓ bundle/delegation verificados
identidad local de Site + identidad de terminal/operador
        ↓ scopes, epochs, expiración y revocaciones
capability y proyecciones locales
        ↓ operación local
datos locales / Site Core
        ↕ transporte, outbox/inbox y fallback autorizado
sync y reconciliación (nunca fuente de permisos)
```

La operación local previamente autorizada queda separada del transporte. Center continúa siendo owner de identidad canónica, políticas, publicaciones y estado deseado; Site Core conserva la autoridad operacional delegada; Node Manager conserva el runtime universal del Host.

## Diferencia M4 vs. Site Runtime histórico

M4 define una jerarquía soberana:

`Product Trust Root → Deployment Authority → Deployment Root → Center Authority → Enrollment Authority`

Release y Product Signing son ramas separadas. Node Manager ya verifica esa cadena para enrollment y bundles de trust.

Site Runtime, en cambio, usa actualmente una autoridad operacional histórica:

- Center Edge Function firma `SiteRuntimeBundleV1` y `SiteAuthorityDelegationV1` con una clave privada configurada en `ACTIUM_SITE_BUNDLE_SIGNING_PRIVATE_KEY_PEM`.
- Site Core verifica esa clave mediante `SITE_RUNTIME_TRUST_ANCHOR_FILE`, issuer y audience.
- La clave local de Site firma tokens operacionales y las proyecciones locales se limitan por scope, epoch, revocación y `offline_until`.

Esto no es equivalente a una cadena M4: `trust_anchor_id` identifica hoy al signer histórico, no un `trust_bundle_id` ni una relación certificada con Center Authority. La corrección adecuada es un adapter/versionado de publicación que haga que Center Authority autorice criptográficamente la delegación operacional existente y que Site Core valide ese vínculo. No se implementó en esta ejecución porque el Authority Service no tiene material productivo y el contrato actual no puede aceptar ese cambio sin una transición explícita de consumidores.

No se creó una segunda Site Authority, no se hizo TOFU y no se aceptó una clave pública por presencia o similitud de identificadores.
