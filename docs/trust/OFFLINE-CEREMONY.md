# Offline Product Trust Root ceremony

## Purpose

The Product Trust Root is a trust anchor, not an online enrollment signer.
The online Authority Service uses only subordinate keys for capability-scoped
operations such as `host_enrollment`, `center_bundle_signing` and
`product_signing`. The root-signed Trust Bundle is prepared offline and then
published as public material.

## Preconditions

The Owner must choose and record:

- offline custody and backup policy for the Product Root;
- recovery policy for the online subordinate provider;
- rotation and revocation policy;
- separate protected sealing-key files for offline and online storage;
- the deployment data directory and the public Trust Bundle destination.

No sealing key is generated by the command. A software-sealed provider is
not a claim of TPM/HSM non-exportability; use a PKCS#11/TPM provider when the
NAS hardware and operational custody actually support it.

## Command

The command is intentionally explicit and refuses existing ceremony outputs:

```text
actium-authority-ceremony \
  --offline-key-dir <offline-root-key-dir> \
  --online-key-dir <authority-data-dir>/keys \
  --offline-sealing-key-file <offline-sealing-key-file> \
  --online-sealing-key-file <online-sealing-key-file> \
  --state-out <authority-data-dir>/authority-state.json \
  --trust-bundle-out <authority-data-dir>/trust-bundle.json \
  --root-authority-id actium-product-root-v1 \
  --confirm OFFLINE_ROOT_OWNER_APPROVED
```

The current implementation accepts `--confirm` as an argument so the
operator action is visible in shell history/audit procedures; it does not
read a private key from an argument. The command creates the hierarchy,
signs the public Trust Bundle with the offline root, copies only subordinate
keys into a staging directory, verifies the durable state, and commits the
online directory. It prints only the root key ID, output path, subordinate
count and the fact that the online root key is absent.

## Activation checks

Configure the daemon with:

```text
ACTIUM_AUTHORITY_KEY_DIR=<authority-data-dir>/keys
ACTIUM_AUTHORITY_SEALING_KEY_FILE=<online-sealing-key-file>
ACTIUM_AUTHORITY_TRUST_BUNDLE_FILE=<authority-data-dir>/trust-bundle.json
```

The daemon must be able to load all non-root references. A state marked with
`publicOnlyKeyIds` is rejected if the root key is present online. A missing or
invalid public Trust Bundle keeps the service degraded and does not enable
signing readiness. `/health` reports process liveness separately from
`authorityState` and `trustBundleState`.

## Recovery and rotation

The command is initial bootstrap only and refuses an existing online key
directory or output. Recovery must restore the exact public state, subordinate
sealed references, and Trust Bundle as one reviewed operation; an old backup
must not lower the durable trust epoch or reintroduce revoked material.
Root rotation continues to use the dual-signature transition contract. The
old root remains an offline signer for the transition and the new root is
accepted only after its signed transition is verified by the existing anchor.
